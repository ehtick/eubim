User: i have a problem with the intended sequence: when launching revit and loading the add-in, revit is asking whether to load it, because it is not signed. is there any way to programmatically prompt it to load always ?
Assistant: No, not through the Revit add-in API.
Autodesk’s docs describe the trust decision as a user action on the security dialog: Always Load, Load Once, or Do Not Load. For unsigned add-ins, the dialog is shown before Revit runs the add-in; for signed add-ins, Revit trusts the publisher certificate once it is in a trusted chain. I don’t see any supported API that lets an add-in programmatically click or pre-answer that dialog. That’s my inference from the docs, not an exposed feature.
What you can do instead is:
1. Sign the DLL with a real Authenticode code-signing certificate from a trusted CA.
2. Have the user choose Always Load once for that publisher/add-in.
3. For managed deployment, use the Revit (Admin) Add-Ins Manager to mark trusted add-ins as Always Load and export AdminSettings.json.
For your case, the practical fix is signing the DLL. If you want, I can wire the project to sign Demo02.dll during build and keep the install flow working.
