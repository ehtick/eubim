Part 4: Architecture Tour – Demo02 & CmdLittleHouse

System Components:

Codex/Demo02/
├── Application.cs (OnStartup, events)
├── Commands/
│ ├── CmdDemo02.cs (Execute, Execute2)
│ └── CmdLittleHouse.cs (Execute, Execute2)
├── signing/ (local certificates)
├── log/ (timestamped output)
└── Demo02.csproj (build + sign)

Pattern: Every external command follows the same architecture. Consistency = predictability = reliability.

Speaker Notes: Show the folder structure on screen. Explain that AGENTS.md documents these patterns so future commands follow the same rules.

Pattern 1: External Command Separation

public class CmdDemo02 : IExternalCommand
{
    public Result Execute(ExternalCommandData data) {
        // Entry point (resolve document)
        return Execute2(doc);
    }

    private Result Execute2(Document doc) {
        // Real work (testable, reusable)
    }
}

Why?

  • Execute: Revit entry point (cannot be tested directly)
  • Execute2: Pure document work (callable from anywhere)
  • Separation enables automated testing and event-driven startup
Speaker Notes: This pattern is the foundation. It's what allows the same command logic to run both on button click and on startup via events.

Pattern 2: Startup Automation

void OnStartup(object s, StartupEventArgs args) {
    app.ApplicationInitialized += OnApplicationInitialized;
}

void OnApplicationInitialized(object s, EventArgs args) {
    app.Idling += OnIdling;
}

void OnIdling(object s, IdlingEventArgs args) {
    if (uiApp.ActiveUIDocument?.Document != null) {
        app.Idling -= OnIdling; // unsubscribe
        CmdDemo02.Execute2(doc);
    }
}

Key: Stay subscribed to Idling until document exists. Only then execute.

Speaker Notes: Show the sequence: OnStartup → ApplicationInitialized → Idling. Explain the timing: Revit may not have a document yet when Idling first fires. We wait for one.

Pattern 3: Digital Code Signing

🔑 Problem: Unsigned assemblies trigger "Load Always / Load Once / Do Not Load" dialog.

Solution: Sign at build time.

<!-- Demo02.csproj -->
<SignAssembly>true</SignAssembly>
<AssemblyOriginatorKeyFile>
  signing/demo02.pfx
</AssemblyOriginatorKeyFile>

Workflow:

  • Once: Generate local certificate, import to trust store
  • Every build: Compile → Sign → Install → No prompts
  • Result: Revit loads add-in silently, executes commands
Speaker Notes: Emphasize that this is a one-time setup cost. After that, builds are 100% automated.

Pattern 4: Comprehensive Logging

Principle: An autonomous system has no eyes. Logs are its vision.

What We Log:

  • OnStartup: When add-in loads
  • OnApplicationInitialized: When Revit is ready
  • OnIdling: When Idling event fires (and whether document exists)
  • Execute, Execute2: When commands run, what they do, results

Format:

C:/Users/j/w/src/eubim/Codex/Demo02/log/
├── 20260515-171210-101-OnStartup.log
├── 20260515-171210-101-ApplicationInitialized.log
├── 20260515-171210-101-OnIdling.log
└── 20260515-171210-101-Execute2.log

Each file is timestamped, sequential, human-readable.

Speaker Notes: Show a real log file on screen if possible. Explain how we verify the system worked by reading these files.

Case Study: CmdLittleHouse

Goal: Build a complete BIM model autonomously, with multiple iterative refinements.

🏠 Create a house with 2 levels, 4 walls, 1 floor, 1 roof, doors, windows—all via AI-generated code, running unattended.

Development Timeline:

  • Iteration 1: Basic geometry (family lookup failures)
  • Iteration 2: Fix geometry (floor, walls, windows, doors)
  • Iteration 3: Refine roof (overhang, attachment)

Codex drove each iteration: "The windows are too low. The roof overhang is too large." Codex fixed code, system reran, logs verified.

Speaker Notes: Emphasize that this is not a trivial "Hello World" command. It's a real geometric modeling task with multiple iterations driven by feedback from log analysis.

Key Insights

1️⃣ AI + Structure = Reliability. Free-form prompts fail. Patterns (AGENTS.md) ensure consistent code.

2️⃣ Signing solves the Revit dialog problem. One-time setup, massive payoff.

3️⃣ Events (ApplicationInitialized, Idling) are the key to autonomy. Not button clicks.

4️⃣ Logging enables autonomous iteration. Logs are the "eyes" the AI uses to verify and refine.

5️⃣ Documentation (AGENTS.md) is foundational. Future commands inherit patterns; developers and AI follow conventions.

Speaker Notes: These are the five pillars. If you remember nothing else, remember these.

Part 5: Lessons & Future (15 min)

What AI Excels At:

  • Boilerplate code (manifests, event handlers)
  • Iteration (refactor, fix, test, refactor)
  • Following patterns (if patterns are clear)
  • Testing and verification (writing log parsers, checking results)

Where Humans Are Still Essential:

  • Defining the problem clearly
  • Creating architectural patterns (AGENTS.md)
  • Interpreting edge cases and failures
  • Making design tradeoffs
  • Understanding business context
Speaker Notes: This is the balanced view. AI is a powerful tool, not a replacement. The future is humans + AI, not AI alone.
