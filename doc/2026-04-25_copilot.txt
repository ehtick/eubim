# Copilot (GPT 5.2)

For **Nice3point/RevitUnit** specifically: **Revit is launched for you** by the framework when you run the tests (e.g., `dotnet test` / `dotnet run` with a Revit-targeting configuration). You don’t normally start Revit manually.

From the repo README:

- Running tests is via `dotnet run` or `dotnet test` with a configuration like `Release.R26`.
- You **must have a licensed Revit installed** that matches that configuration.
- Tests execute on Revit’s single-threaded API context using `RevitThreadExecutor`.

```bash
cd C:/Your/Test/Directory
dotnet test -c "Release.R26"
# or
dotnet run  -c "Release.R26"
```

Source: `Readme.md` in the repo (see “Running your tests” and “IMPORTANT” note).

## 4) The RevitUnit testing model you’ll lean on

RevitUnit is built around TUnit and a base class like `RevitApiTest`, plus an executor `RevitThreadExecutor` to ensure API calls happen on Revit’s thread.

Your tests generally look like:

- create a new project document in a `[Before(Test)]` hook
- run a transaction to seed model elements
- call your pure logic functions **or** directly invoke your command logic (recommended: split command into “command wrapper” + “core service”)
- assert via collectors / element parameters
- close document in `[After(Test)]`

This pattern is already in their README and examples, and it’s the right approach for repeatability.
